# Chat assistant (Bani)
- Bani contextual memory lives in chat-assistant `contextMemory.ts`: past record notes plus `bani_memory_notes` (server-written, venue/supplier scoped) are injected as untrusted background, never as rules; post-scan verdicts come from deterministic scanner checks, not extra model calls.
- Bani action cards: chat-assistant `propose_action` writes a row to `bani_pending_actions` (service-role only, no client grants) and streams an `action_card` event; FloatingBani renders Confirm/Cancel and calls back with `action_id`+`decision`, where the server re-validates ownership, expiry (30 min), single-use status, and re-checks sales conflicts before executing. Card titles for closed days are computed server-side from the validated venue/dates — never trust the model's title. Closed days are only markable for yesterday or earlier (Asia/Hong_Kong).
- Bani must never infer missing sales days from aggregates: `get_missing_sales_days` (chat-assistant) is the authoritative check (no sales AND no closure, through yesterday); `get_venue_closures` exposes closed days so they are never flagged as missing.
- Multi-day gap dialogue uses `missingSalesConversation.ts` with per-date weekday/prior-sales evidence from the authoritative tool; absent history never proves closure, and mixed gaps retain unresolved dates until explicitly classified. Selected closed dates share one existing confirmation card per venue; traded dates retain the one-file sales scanner.
- Main chat loads tenant `general`/`venue` bani_memory_notes as untrusted background and saves lasting facts only via `save_memory_note`; `ai_learned_rules` stays the deterministic scanner cache. Waste uses the `log_waste` card (`wasteActions.ts`), inserting as the user only on Confirm.
- Navigation uses navigationRules.ts on server/client; record inspection uses requester RLS plus access/money/venue checks. Ordinary bill and receipt cards use atomic owned-card RPCs with stale-source checks. Bills require typed posting review; only unchanged receipt clears offer timed Undo. Disputes and recurring/asset/split bills retain their existing page workflows.
- Planning/what-if talk uses read-only analyze_revenue_goal (planAnalysis.ts) plus render_chart/markdown tables; FloatingBani renders streamed chart events; save cards come only after the user commits, so analysis never writes.
- Read-only get_menu_margins (menuMargins.ts) serves dish cost/price/margin from saved recipes; single-venue tenants auto-resolve venue in People tools and prompt.
- Chat open-items reads missing dates through the live get_missing_sales_days tool; missingSalesConversation keeps current status distinct from historical evidence and restores a picker on unresolved clarification turns, so summaries cannot substitute yesterday-only snapshots.

- recordStatus.ts maps overdue inspection to due/payment filters rather than approval statuses; open-items includes paginated overdue invoice/bill detail, so next-item conversation can retrieve records rather than guessing from aggregates.
