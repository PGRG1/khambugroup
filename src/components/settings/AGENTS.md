# Settings
- Settings destinations resolve through settingsNavigation.ts with legacy query compatibility; the page gate retains admin/preview and invoice-only Master data access, so navigation never grants access.
- Focused editors reuse existing tenant-scoped hooks, mutations and atomic RPCs; query destinations change presentation only, and long work renders in the detail pane rather than a containing modal.- Settings is Rillet-style and plain: a text menu (groups Organization · Team · Operations · Accounting · Lists · Bani, an orange dot where useSettingsSummary finds something missing) beside one page per setting on computer and tablet; on phone the menu, then the page with ‹ Settings. Pages are plain: group label, title, one short line, then forms built from SettingsForm.tsx (Field rows, one Save changes; Choice for single choices, saved on tap; PlainList for added things). No cards, chips or summary numbers inside Settings. Each venue uses tabs Seats · Service periods · Closures · Stock areas · Location · Status. A venue's account mapping lives only in Finance › Accounting › How things post.
