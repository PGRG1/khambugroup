# Settings
- Settings destinations resolve through settingsNavigation.ts with legacy query compatibility; the page gate retains admin/preview and invoice-only Master data access, so navigation never grants access.
- Focused editors reuse existing tenant-scoped hooks, mutations and atomic RPCs; query destinations change presentation only, and long work renders in the detail pane rather than a containing modal.- Settings is Rillet-style: on computer and tablet its pages sit under Settings in the main menu (AppSidebar SettingsSubNav, shown only on /settings, grouped, orange dot from useSettingsSummary); the page itself has no second menu. Each page is one glass panel (max 900px): 20px title, page action (Add/Invite) top-right via PageAction, then sections from SettingsForm.tsx — SettingsCard with a title is name-left/values-right with one Edit (Row values, Field + SaveBar while editing); untitled SettingsCards holding lists run full width with 44px rows and soft alternate shading. Choice saves on tap. No lines, no summary numbers, no explainer notes, no record IDs or code names (Activity log reads as plain sentences in AuditLog.tsx). On phone: the grouped list, then the page with ‹ Settings, sections as glass cards. Merged pages via mergedInto: Purchasing & stock, How your team works, Books setup (opening balances read first in OpeningSummary; Edit opens the embedded editor). Card processors: one section per processor; Edit opens the existing editors (?edit=1). Company, venues and users stay read-only unless Bani (see root AGENTS.md). Each venue uses tabs Seats · Service periods · Closures · Stock areas · Location · Status. A venue's account mapping lives only in Finance › Accounting › How things post.
