# Settings
- Settings destinations resolve through settingsNavigation.ts with legacy query compatibility; the page gate retains admin/preview and invoice-only Master data access, so navigation never grants access.
- Focused editors reuse existing tenant-scoped hooks, mutations and atomic RPCs; query destinations change presentation only, and long work renders in the detail pane rather than a containing modal.- Settings uses read-first glass cards on the green: a settings list card (groups Organization · Team · Operations · Accounting · Lists · Bani, orange dot from useSettingsSummary) beside one page on computer and tablet; on phone the list, then the page with ‹ Settings. Pages: group label + title, page actions (Add/Invite) top-right via PageAction, then SettingsCard blocks from SettingsForm.tsx showing saved values as Row with one Edit per card (Field rows + SaveBar while editing); Choice cards save on tap; lists sit inside cards. No lines inside cards, no summary numbers, no explainer notes. Merged pages via mergedInto: Purchasing & stock (purchasing+stock), How your team works (approvals+team), Books setup (books+opening). Card processors show one card per processor (merchants, fee range); Edit opens the existing editors (?edit=1). Each venue uses tabs Seats · Opening hours (service periods + closures) · Stock areas · Location · Status. A venue's account mapping lives only in Finance › Accounting › How things post.
- Client Settings only holds what a client runs day to day. Business = Company (read-only for clients, one card) + Venues (mergedInto venues→company; clients change seats, service periods, closures, stock areas and location only). Books setup is baniOnly: shown only to Bani platform admins (visibleSettingsDestinations third arg); the control plane shows it in ClientBooks with Edit entering the client.- Settings has one menu: on computer and tablet its pages sit under Settings in Bani's main menu (AppSidebar SettingsSubNav when on /settings; the collapsed rail's Settings pop-up lists them too); the page shows only the open page, built like Revenue and Purchasing from SettingsForm.tsx: 24px title with one white PageAction beside it, kit cards (SettingsCard: title on top, one Edit), saved values as a label-over-value grid (Row), Field + SaveBar while editing, Choice options side by side saved on tap, lists full width. No box inside a box; tables use the same thin row lines as every other Bani table; no warning rows (status shows amber). Lists (People) follow Team/Supplier accounts: one card with the count as heading, Toolbar (filter, search) inside, rows open on tap, "No people yet." when empty. On phone: the grouped list, then the page with ‹ Settings. Each venue uses tabs Seats · Service periods · Closures · Stock areas (Status for Bani only), built in VenueTabs.tsx as plain cards (tables on computer, two-line rows on phone); Location (staff clock-in) is hidden for now and VenueLocationTab is kept for later. A venue's account mapping lives only in Finance › Accounting › How things post.
- Revenue setup (Accounting group, RevenueMapping.tsx): venue tabs, one table Report line · Type · Settles to · Account; Edit (Bani or Approve on Finance) makes a draft, rows open the line editor, unknown printed names from recent and held reports show as rows to finish, Next asks the start date, Save makes a new version. History and held days are their own cards.
- Purchasing setup (Accounting group, PurchasingSetup.tsx): venue tabs, one table Category · Group · Account · Products; Edit makes a draft, rows open the category editor (group for categories without one, account same for all venues or per venue), Save makes a new version (no start date: posted invoices never change). History and held invoices (linked to the invoice) are their own cards.
- Setup (Organization, first page, ClientSetup.tsx): one table Step · What · Status · Open for the 7 steps; Books shows "By Bani" for clients. Categories (Lists, ClientCategories.tsx): one table that opens like folders — Category (indented, arrow to open) · Level · Group · Account (Level 1 rows, from Purchasing setup rules, else the products' group; "No account" amber) · Products · Tidy (Same as …, or "N to tidy" on a closed parent); summary line, Expand all, search opens matching branches, Add category (new Level 1); a row opens a panel to add the next level under it or Merge. Phone: a settings-menu drill-down (tap a category to go in, ‹ back, product counts, group · account on top categories, amber notes under the name, Merge on a duplicate, "+ Add under …" at the bottom of each level).
- Settings menu (since Nov 2026): one item per group — Business (Setup · Company · Venues · Sales sources), People (Logins · Approvals · Activity log), Accounting (Revenue setup · Purchasing setup · Card processors · Chart of accounts · Tax · Currency · Schedules · Books setup), Operations (How you buy · Stock counts), Master data (Suppliers · Products · Categories), Bani. A group's pages are Finance-style view tabs (invoice-switch, like Books) above the page title on every screen size; groups and order come only from settingsDestinations in settingsNavigation.ts. Chart of accounts (with How things post), Tax, Currency and Schedules moved back from Finance › Books (old Books links redirect).
- Master data › Suppliers & vendors (MasterDataTab SuppliersList): a setup list in the Sales records layout — count heading (suppliers · vendors), Type and Status filters + search, one line "N possible duplicates · N missing a contact · Show them" (merge and add-contact links inside), table Name · Type (Supplier = stock invoices, Vendor = bills, from suppliers.vendor_type) · Supplies · Payment terms · Contact · Phone · Status; missing setup shows amber Not set; no invoice counts.
