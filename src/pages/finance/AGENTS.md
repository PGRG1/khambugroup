# Finance rules
- Reports use financeReportViews/FinanceAging for read-only balances, due terms and capped payment proposals; ManagementReports retains typed adjustments.
- Schedule settings and deferred items are tenant-scoped, RPC-written; finance_entry_drafts is read-only to clients. Explicit expense_month_approve selections own schedule posting, with current source and closed-period rechecks; page loads never prepare or post.
- Month close uses server snapshots and append-only explanations; triggers require completeness and block unexplained/matching/correction exceptions. Guarded actions own writes.
- PeriodControl/periodWindow owns Finance date windows and session selections; useBooksWindow resolves Accounting configuration and tax year, and Finance checks only request bounded months so malformed journal dates never create menu years or extra checks.
- Invoice asset proposals route source debit at selected approval; create register/depreciation only then. Posted invoices use compensating drafts, and posting rechecks source fingerprints and counted delivery. Existing sales deferred edits use guarded source RPCs; posted days retain originals with reversal/rebook drafts, FIFO balances rechecked at approval. Previously deferred/grouped sources fail closed until reconciled.
- StatementReviewQueue owns multi-file review; existing bank/settlement commits and identity-scoped utility handoff own imports. Unknown type/account requires explicit selection, queue duplicates use byte hashes; filenames alone are never trusted as document evidence.
- Schedule RPCs recheck sources at selected approval. Deferred sales bypass normal rebuilds and receipt auto-post. Unpaid bank proposals delegate payment creation and matching only at selected monthly approval with source fingerprints; account merge authorization is independently server-checked, never broadens schedule approval. Tax notices are append-only non-ledger due evidence. Asset bills capitalize during guarded source approval; advance bills fund pending day-based releases only on approval. Central shares are report-only; sales merchant aging uses matched gross tender evidence, leaves ambiguous mappings explicit, and remains separate from ledger aging.
- Foreign currency: `src/utils/money.ts` is the only ISO money formatter (base set once by AppLayout from tenants.base_currency, server-locked after first posted journal). Rates come only from `fx_rate(tenant,date,currency)` (tenant overrides in bank_fx_rates, else global fx_reference_rates, nearest previous date flagged). Foreign documents keep original_total/fx_rate with base amounts = original × rate; new journal lines inherit currency/rate from their source by trigger; existing lines are never rewritten. Gains/losses and revaluation are part 2.
